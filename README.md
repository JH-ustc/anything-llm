## 本 Fork 的本地适配

这是 [Mintplex-Labs/anything-llm](https://github.com/Mintplex-Labs/anything-llm) 的个人 fork，基线为 **v1.19.0**，用于本地优先的个人学习与研究工作台。保留 fork 的目的不是另起产品，而是把本地部署所需的小补丁、中文文档和升级节奏固定下来，避免每次重装或升级重复踩坑。

### 维护的补丁

| 提交 | 文件 | 作用 |
| --- | --- | --- |
| `9848d5e` | `server/utils/agents/aibitat/providers/helpers/dsml.js`、`tooled.js` | 恢复 DeepSeek V4 在并行或畸形包装下泄漏到正文的 DSML 工具调用，并在流式输出中过滤标记；附带单元测试 |
| `e0edd65` | `frontend/src/hooks/useAutoScroll.js`、`frontend/src/components/WorkspaceChat/ChatContainer/ChatHistory/index.jsx` | 用户向上阅读时不再被自动拉回提问位置：只在发送新消息时重新跟随，任何向上滚动解除跟随，并关闭浏览器滚动锚定 |
| `5a848b8` | `README.md`、`locales/` | 仅保留简体中文 README，其他语言版本归档 |

### 本地部署形态

- Windows + WSL Ubuntu + Docker Desktop；镜像固定为 `mintplexlabs/anythingllm:1.19.0`，不跟随上游滚动更新。
- 服务仅监听 `127.0.0.1:3001`，不对外网暴露；关闭遥测。
- 检索使用本地 `MintplexLabs/multilingual-e5-small` 嵌入 + LanceDB；对话模型通过 DeepSeek 官方 API。
- 后端补丁文件与前端构建产物（`frontend/dist` → `/app/server/public`）都以只读 bind mount 覆盖进容器，应用数据与向量库持久化在宿主机。
- Docker Desktop 未设置开机自启；冷启动时容器可能抢在 WSL 文件集成就绪前启动，需要等引擎完全启动后手动执行 `docker start anythingllm`。

### 同步约定

- WSL 本地 clone 是开发工作副本；每次改动都提交并 push 到本 fork 的 `master`，保持两边一致。
- 上游更新按需合并，不盲目跟进；合并前先确认本地补丁与部署挂载仍然兼容。
- 提交信息使用英文 conventional commit。

### 产品概览

AnythingLLM 是一款全方位 AI 应用程序，让您毫无妥协地构建私有的、功能完备的 ChatGPT。接入您喜爱的本地或云端 LLM，导入您的文档，几分钟内即可开始聊天。开箱即用即可获得内置智能体、多用户支持、向量数据库和文档处理管道——无需额外配置。

AnythingLLM 还支持多用户，您可以控制每个用户的访问权限和使用体验，同时不会损害实例的安全性、隐私性或您的知识产权。

### 技术概览

本单一仓库由六个主要部分组成：

- `frontend`: 一个 viteJS + React 前端，您可以运行它来轻松创建和管理 LLM 可以使用的所有内容。
- `server`: 一个 NodeJS express 服务器，处理所有交互并负责向量数据库管理与 LLM 交互。
- `collector`: NodeJS express 服务器，用于从 UI 处理和解析文档。
- `docker`: Docker 指令、构建流程以及从源码构建的相关信息。
- `embed`: 用于生成和创建[网页嵌入组件](https://github.com/Mintplex-Labs/anythingllm-embed)的子模块。
- `browser-extension`: 用于 [Chrome 浏览器扩展](https://github.com/Mintplex-Labs/anythingllm-extension)的子模块。

## 如何设置开发环境

- `yarn setup` 填充应用各部分所需的 `.env` 文件（在仓库根目录执行）。
  - 请先填写这些文件再继续。确保 `server/.env.development` 已填写，否则程序无法正常运行。
- `yarn dev:server` 在本地启动服务器（在仓库根目录执行）。
- `yarn dev:frontend` 在本地启动前端（在仓库根目录执行）。
- `yarn dev:collector` 然后运行文档收集器（在仓库根目录执行）。
